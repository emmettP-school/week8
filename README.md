# week8
DriverPass System Design

For this project the client was DriverPass. The ownes asked me to design an online system to replace the phone calls and paper they run on now. Customers use it to book sessions and study for the driver test while admins use it to look at their schedule or to help the customers schedule.

What I did well

I like how I kept the design short and sweet because they didnt ask for something with a lot of bells and whistles, while also leaving room for it to improve.

What I would revise

If I could revise the end design I wish I had made it so Liam can make packages without dev help from the get go.

Interpreting user needs

I took what the interview and turned what they asked for into diagrams or slides they can easily understand. For example: Liam wanted to know who changed a reservation, so that became the activity log. 

How I approach design

I start with a lot of note taking on the requests, that way I have a clear view of the vision to communicate it to the other devs. I like using process and object modeling, since the activity diagrams show the order things happen and the class diagram shows what the system stores, and I need both to see the whole picture.
